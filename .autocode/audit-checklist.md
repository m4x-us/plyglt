## Concurrency Safety
[ ] `store/srsStore.ts` — Zustand store writes are synchronous in the JS event loop, but `createPlatformStorage` routes writes to Tauri Store asynchronously via IPC; a rapid sequence of `setState` calls may queue multiple async writes. Verify that Tauri Store serializes writes on the Rust side to prevent last-write-wins corruption when multiple Zustand slices flush simultaneously.
[ ] `hooks/useExportImport.ts:readFile` — `FileReader.onload` calls `useSRSStore.setState()` then `useEntitlementStore.getState().setEntitlement()` sequentially without a transaction. If the component unmounts between these two writes (user navigates away), the SRS store is updated but entitlement is not, leaving the two stores inconsistent. Verify that `handleImportFile` cannot be triggered from a component that the user can unmount mid-flight.
[ ] `components/InterruptHandler.tsx:InterruptHandlerCore` — `listen("interrupt:fire", ...)` is called in a `useEffect` and the unlisten function is captured via `.then(fn => { unlisten = fn; })`. If the component unmounts before the Promise resolves, `unlisten` is never assigned and the listener leaks. Verify that there is a guard or that the async gap is acceptable given Tauri's event system guarantees.
